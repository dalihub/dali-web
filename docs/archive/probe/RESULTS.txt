Special findings / 특이 사항
  - Core compilation and the selected animation path required no source changes.
    This removes an initial uncertainty but does not prove all Core behavior.
  - Native EGL pixmap/copy paths need exclusion or an actual web replacement.
    Unsupported advanced blend behavior requires capability handling; silently
    replacing required semantics with no-op functions would be incorrect.
  - FULL_ES3 alone is insufficient for the current Memory3 mapping call:
    it passes only GL_MAP_WRITE_BIT. SDK libwebgl.js requires an INVALIDATE flag
    as well. Compare the existing Memory2 BufferSubData path against a carefully
    specified mapping alternative; do not blindly change preservation semantics.
  - The SDK's glProgramBinary implementation always reports an error. The
    adaptor defaults shader binary usage on; a web profile needs it disabled
    (DALI_SHADER_USE_PROGRAM_BINARY=0) and source compilation verified.
  - Native resource/surface context sharing is not reproduced by the SDK EGL
    implementation. A first web target should explicitly specify one canvas
    and one context, then adapt resource uploads and rendering to that model.
  - The production thread controller compiles, but its waits and startup
    synchronization have not been executed in a browser. Compilation does not
    establish browser thread compatibility.

Reproduce in this prepared directory
  bash build-core.sh
  bash probe-adaptor.sh
  python3 probe-gl-symbols.py
  python3 check-browser.py

  check-browser.py requires permission to launch local Firefox/geckodriver
  and bind loopback sockets. It terminates its browser and local server.
  probe-gl-symbols.py intentionally records failed links and exits normally;
  inspect exitCode in logs/gl-symbols.json for each link result.
  All builds use at most six parallel compile jobs.
