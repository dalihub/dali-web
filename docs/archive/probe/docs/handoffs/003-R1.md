## 시작할 때 할 일

1. 원격 dali-web의 현재 상태와 로컬 대상 경로 `/home/jy/work/dali/dali-web` 존재 여부를 확인합니다. 빈 repo라는 과거 기록만 믿고 기존 변경을 덮어쓰지 않습니다.
2. 원본 repo와 실험 복제본의 Git 상태·revision·remote를 확인합니다. Core·Adaptor는 현재 Tizen 원본 commit이므로 GitHub 미러에서 접근 가능한지 검사합니다. UI의 import 기준도 선정합니다.
3. PLAN의 구조를 기준으로 초기 repo 뼈대와 생성물 제외 규칙을 준비합니다. 라이브러리는 `libs/dali-core`, `libs/dali-adaptor`, `libs/dali-ui`에 둡니다.
4. squash 이력 정책을 결정·기록하고 원본 URL·prefix·기준 SHA를 lock 파일에 남깁니다. upstream remote를 복원할 개발자용 스크립트를 마련합니다.
5. subtree import 결과와 라이선스 보존, 중첩 Git 메타데이터·생성물 제외를 확인합니다. commit 시 현재 세션 모델명으로 정확히 한 개의 AI co-author trailer를 확인합니다. 공개 push는 실행 지시 범위를 확인합니다.
6. R1 완료 후 R2용 HANDOFF를 작성합니다. 실험 경로 변경·재빌드는 R2에서 수행하고, 신규 렌더러 구현은 섞지 않습니다.

## 반복하지 않을 조사

- SDK는 이미 tools/에 설치돼 있습니다. 재설치할 필요가 없습니다.
- Core 전체 빌드와 선택한 애니메이션 테스트는 Node·Firefox에서 통과했습니다.
- Adaptor 주요 6개 파일은 이미 em++ 컴파일을 통과했습니다.
- 기본 링크 탐색은 7개, FULL_ES3에서는 3개 심볼이 미해결입니다. 그것만 고치면 전체 포팅이 끝나는 것은 아닙니다.
- GLES 3.2 헤더가 없을 것이라는 가설은 이번 SDK에서는 맞지 않았습니다.

## 중요한 제한

실제 픽셀은 아직 검증하지 않았습니다. `core-smoke.cpp`의 모의 Graphics Controller를 생산 렌더링 증거로 사용하지 않습니다. GL 심볼 탐색에서 생성한 선언은 링크 검사 전용이므로 실행용 래퍼로 재사용하지 않습니다.

원본 저장소는 이전 검증에서 수정하지 않았으며, 이번 작업도 문서만 갱신했습니다. 컨텍스트 공유·생산 스레드·Windows 동작은 미검증입니다. 미지원 기능을 빈 함수로 숨기지 않습니다.

## 필요한 경우 재현

작업 디렉터리는 `/home/jy/work/dali/webassembly-probe`입니다.

```sh
bash build-core.sh
bash probe-adaptor.sh
python3 probe-gl-symbols.py
python3 check-browser.py
```

변경 영향이 있을 때만 필요한 검증을 재실행합니다. 기존 스크립트는 logs의 같은 파일을 덮어쓰므로 먼저 관련 로그를 별도 실행 디렉터리에 복사합니다. 브라우저 검증은 로컬 서버·Firefox 실행 권한이 필요할 수 있습니다. 심볼 탐색 스크립트는 링크 실패를 JSON에 기록하고 자체 종료 코드는 0일 수 있습니다.
